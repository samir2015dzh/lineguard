# lineguard 整体思路
---

## 1. 它是什么，解决什么问题

**一句话：** 让这台 Windows 电脑的所有流量只从你的独享线路（自建节点或机场订阅）出去；线路断了就直接断网，**真实 IP 绝不漏出去**。

普通代理软件的思路是“把流量**引**到代理”：代理一坏、一退出，或者某个程序不走系统代理，流量就悄悄直连出去了，泄露是看不见的。

lineguard 反过来：

- **默认全部禁止**：在 Windows 防火墙最底层装一套“断网规则”，除了局域网和节点服务器，所有外网一律拦。
- **代理内核是墙上唯一的门**：只有经过内核、进了加密隧道的流量才能出去。
- 出任何问题（内核崩溃、节点挂了、规则被改、电脑重启那几秒），结果都是**断网**，而不是**直连**。

> 设计底线：**宁可断网，也不漏。*

## 2. 整体结构

```
┌──────────────────────────── 用户的 Windows 电脑 ────────────────────────────┐
│                                                                              │
│  界面 lineguard-app（Vue + Tauri，托盘）      命令行 lineguard.exe            │
│            │  命名管道（本机，按会话鉴权）           │                       │
│            ▼                                         ▼                       │
│  ┌──────────────── 后台服务 lineguard-daemon（SYSTEM，开机自启）──────────┐  │
│  │ 状态机：保护 / 暂停 / 关闭 / 断网（原因）                              │  │
│  │ ├─ 断网规则 killswitch ── Windows 防火墙底层（WFP），持久 + 开机两套   │  │
│  │ ├─ 内核管理 kernel ────── mihomo（TUN 虚拟网卡、DNS、选线路）          │  │
│  │ ├─ 网卡设置 netcfg ────── DNS 指向本机、物理网卡 IPv6 关闭（可还原）   │  │
│  │ ├─ 订阅与线路 links/configgen ─ 解析订阅 → 生成内核配置 → 放行前自检   │  │
│  │ ├─ 安全检查 selfcheck/checks-env ─ 30 项，含真实泄露探测               │  │
│  │ ├─ 冲突检测 conflicts ─── 别的 VPN / 代理 / 系统代理                   │  │
│  │ ├─ 系统设置 sysprefs ──── 浏览器 WebRTC 策略、时区                     │  │
│  │ └─ 更新 update ────────── 查签名清单、下载、校验、静默覆盖安装         │  │
│  └────────────────────────────────────────────────────────────────────────┘  │
│  急救 lineguard-rescue（独立程序）：撤规则、还原网卡，卡在断网时用            │
└──────────────────────────────────────────────────────────────────────────────┘
          │ 加密隧道（Reality / SS / Trojan / Hysteria2 / AnyTLS …）
          ▼
   节点服务器（自建或机场）  ──►  互联网

   探针服务器（lg-probe）：给“泄露检查”当靶子，看有没有包绕过隧道直接到达
   公开发布仓库：放安装包和签名的版本清单，给一键更新用
```

**为什么要拆成后台服务 + 界面：** 断网规则、网卡设置、虚拟网卡都要管理员权限，而且必须开机就生效、界面关了也继续生效。所以真正干活的是以 SYSTEM 身份运行的后台服务；界面只是遥控器，关掉不影响防护。

## 3. 防泄露怎么做到（核心）

### 3.1 断网规则（WFP）

- 用 Windows 筛选平台（WFP）在系统最底层装 **27 条规则**（原版 23 条 + 本地版加的 4 条 DHCP 放行），覆盖 IPv4 / IPv6 的连接层、IP 包层、连入层。
- 规则思路：**放行**回环、TUN 虚拟网卡、局域网、节点服务器 IP；**拦截** DNS 直连（53 / 853 端口）和其余一切。
- **两套同时装**：
  - **持久规则**：系统启动后一直生效，服务崩了也还在。
  - **开机规则**：Windows 启动早期、服务还没起来时就生效，堵住开机那几秒。
- 每 60 秒复核一次，被别的软件改了就重装，并重启内核。
- **DHCP 放行**（实测后加的）：换 Wi-Fi、睡眠唤醒后电脑要重新向路由器申请 IP，原来被拦住就一直断网。只放 UDP 68↔67、出站只到 255.255.255.255 广播，不能被借来绕过隧道。

### 3.2 内核与 DNS

- 内核是 mihomo，开 TUN 虚拟网卡接管所有流量，DNS 用 fake-ip。
- 网卡 DNS 指向本机，由内核统一解析，DNS 查询也走隧道；直连 DNS 被规则拦住。
- 节点用域名的，先在本机用 DoH（按 IP 访问的加密 DNS）解析成 IP，再放进放行名单——**放行名单只认 IP**，不然规则没法精确放行。

### 3.3 IPv6

三层一起堵：规则拦截 IPv6 出站、物理网卡 IPv6 关掉（关闭防护或卸载时还原）、内核不用 IPv6。纯 IPv6 节点会被跳过并说明原因。

### 3.4 放行前自检

生成内核配置后、真正放行前，先跑一遍校验：DNS-LOCK 组只含真实节点、节点域名都有固定 IP、泄露探针不在放行范围里……任何一项不过，宁可保持断网。

## 4. 状态和流程

| 状态 | 网络 | 怎么进入 | 怎么离开 |
|---|---|---|---|
| **已保护** | 只从节点出去 | 有线路、规则装好、内核正常 | — |
| **已断网**（带原因） | 除局域网全拦 | 没线路 / 所有线路连不上 / 内核起不来 / 规则装不上 / 配置有问题 | 原因消失后自动回到已保护 |
| **已暂停** | 直连 | 点“暂停 10/30/60 分钟”、登录公共 Wi-Fi | 到时间自动恢复，或点“马上恢复” |
| **已关闭** | 直连 | 点“关闭防护”、运行网络急救 | 只能手动点“打开防护”；重启电脑也保持关闭 |

几个关键流程：

- **首次安装**：装好就断网（没有线路就没有出口）；导入第一份订阅时临时撤规则下载，下载完立刻装回。
- **线路检测**：保护中每 60 秒真的经节点访问一次外网；当前线路不通就换，全都不通连续两次 → “所有线路都连不上”。
- **网络变化 / 睡眠唤醒**：网卡地址变了，或墙钟比单调钟多走 30 秒以上（说明刚睡醒），马上重新申请地址、断开旧连接、重测线路。虚拟机实测断开网卡再连上 **4 秒恢复**。
- **选线路**：每条连测 3 次、保留最近 8 次，按“中位延迟 + 抖动 + 丢包”综合打分，不被一次偶然的快结果骗。
- **急救**：先通知后台“关闭防护”，再撤规则、还原网卡；后台服务保留，首页点“打开防护”就回来。75 秒限时，每一步写日志。

## 5. 线路从哪来

- **订阅**：机场订阅和自建订阅都支持。请求时报 Clash Verge 的标识，拿到最全的 Clash YAML；也支持 Base64 分享链接。读 `subscription-userinfo` 显示已用流量和到期时间。
- **分享链接**：vless（Reality / TLS / ws / gRPC / xhttp）、vmess、trojan、ss（含 SS2022 和插件）、hysteria / hysteria2、tuic、anytls。
- 自动去掉机场的“提示信息假节点”（到期、剩余流量、官网……）和完全重复的节点；按节点名识别地区（国旗、中文国名、英文代码）。
- **自建节点**：`server/deploy-node.sh` 一键装 Reality（443）+ SS2022（8443）+ BBR，打印两条分享链接。

## 6. 安全检查（30 项）

| 组 | 查什么 |
|---|---|
| 电脑环境 E1–E10 | Windows 版本、权限、系统时间、安全软件、虚拟网卡驱动、磁盘、开机自启 |
| 防护 P1–P8 | 断网规则、防火墙、组件、线路接入、所有流量走线路、网址解析、浏览器 WebRTC 保护、暂停状态 |
| 泄露 L1–L10 | 网站看到的 IP、绕开线路的连接 / 网址查询、网址解析不经国内、浏览器看到的 IP、浏览器绕开线路、**IPv6 泄露**、绕开线路的软件、一分钟抓包观察、真实浏览器实测 |
| 其他 C1 / S3 / S4 | 时区和出口一致、线路质量、线路速度 |

泄露检查靠**探针服务器**：程序故意绕开隧道去连探针，探针收到了就说明有漏洞，收不到说明被堵住了。探针只应答、不记录。能一键修复的：浏览器 WebRTC 策略（P7）、时区改成出口所在地（C1）。

## 7. 安装、更新、急救

- **安装启动器**（`lineguard-<版本>-setup.exe`）：自带安装包和管理员清单；先找一个真能写的临时目录再运行，解决“安装程序不能创建目录”的报错。
- **覆盖安装**：新版直接装在旧版上，线路、设置都保留，装完自动回到保护。虚拟机实测 15/15。
- **一键更新**：启动 20 秒后、之后每 6 小时查一次公开仓库里的 `latest.json`。
  - 清单用 ECDSA P-256 **签名**，客户端内置公钥，用 Windows 自带加密接口验签；
  - 安装包按清单里的 SHA-256 和大小校验，只认公开仓库的下载地址；
  - 被篡改的清单或安装包一律拒绝。虚拟机 0.2.0 → 0.2.1 实测 11/11，用时 67 秒。
- **卸载**：撤两套规则、还原 DNS 和 IPv6、还原时区和浏览器策略、删数据。
- **网络急救**：桌面上单独一个图标，卡在断网时一键恢复上网。

## 8. 给用户的体验

- 深色界面，4 页：**首页**（状态、路线图、当前线路、实时网速、检查摘要）、**线路**、**安全检查**、**设置**，加首次向导。
- **冲突提示**：检测到别的 VPN、代理或系统代理时首页黄条提示，系统代理一键关；打开防护前先确认。
- **诊断报告**：设置 → 出了问题 → 导出到桌面，自动去掉密码、UUID、密钥、订阅 token。
- 关窗口只是收到托盘，第一次会提醒“防护还在后台”；要彻底退出用托盘里的“彻底退出”。

---

## 9. 隐私和安全

- **配置加密**：线路配置（节点密码、密钥、订阅网址）用 Windows DPAPI 加密存盘，只有这台电脑能解开。
- **数据目录**只有 SYSTEM 和管理员能读写。
- **不回传任何东西**：没有统计、没有遥测，软件不会把用户的数据发给任何人。
- **发布包不带本机信息**：打包时把源码路径换成通用名字，程序里搜不到开发者的用户名和目录。
- 软件里能看到的外部地址只有两个：一键更新的发布仓库地址、探针服务器的地址。

## 11. 怎么保证质量

- **单元测试**：约 300 项，覆盖规则表、状态机、订阅解析、签名校验、脱敏等。
- **虚拟机回归**（`tools/vm/regress.sh`）：32 项，会真的动防火墙和网卡——安装、进入保护、出口是节点、订阅、关闭 / 打开、暂停、杀内核后断网并自动拉起、重新申请地址、断开网卡再连上、急救后关闭与恢复、配置加密、深度检查、卸载干净。
- 专项测试：覆盖安装 15 项、安装启动器 5 项、一键更新 11 项。
- **真实环境**：用真实机场订阅、自建节点和探针服务器实测；用户在自己电脑上实装实测。
- 原则：**改到系统的东西只在虚拟机里测**；不动系统的（解析、配置生成）在本机测。
